# Agent 改善 F 阶段分析报告：长期记忆、跨会话、冲突与遗忘

## 给技术新手的摘要

F 阶段把“聊天里提到过”与“项目以后都应记住”彻底分开了。Agent 可以从用户明确说出的
约束、决定、偏好、未决任务和精确值中建立候选，但候选默认只是 `proposed`，不会因为模型
觉得重要就自动变成事实。作者接受后，它才会以 `accepted` 状态进入同项目、同视角分区的
新会话。

这层记忆不复制世界观图谱事实，也不复制作品正文。它保存的是有来源的创作指导，并记录原始
消息 ID。新会话既能看到已接受内容，也能通过受限工具找回仍存在的原文。项目、作者/角色/
观众视角或角色 ID 不匹配时，服务端拒绝来源读取。

## 模块与数据结构

- `ProjectMemory`：记忆正文、主题、类型、作用域、来源性质、版本、适用时间和状态。
- `ProjectMemorySource`：只保存消息/手动决定等引用，不复制原文。
- `ProjectMemoryTombstone`：只保存被遗忘内容的指纹和原因，不保留被遗忘正文；后台再次看到
  同一来源内容时会跳过，防止“删完又长回来”。
- 状态为 `proposed / accepted / disputed / superseded / deleted`。只有当前适用的
  `accepted` 会进入模型请求。

数据库版本从 `e3a6f7b8c9d0` 增量升级为 `f4b7c8d9e0a1`。迁移只新增三张表和索引，
没有删除或改写旧列。

## 候选、接受与跨会话召回

候选只从真实用户消息的明确线索中确定性提取；assistant 回复和 reasoning 不能成为来源。
相同作用域、类型和规范化内容使用 SHA-256 指纹去重，多次出现会增加来源而不是复制多条
记忆。作者也可以在 UI 手动创建“作者决定”，它会直接成为 accepted，并清楚区别于
“Agent 建议”。

每轮上下文从主数据库重新查询已接受记忆，没有另建容易陈旧的长期缓存。请求清单记录 memory
ID，提示块同时包含来源 ID。`read_conversation_sources` 现在也可以接收 memory ID，在服务端
重新校验项目和精确视角分区后读取跨会话原文。

## 冲突与版本

同一规范化主题出现不同有效内容时，不使用 last-write-wins。有关条目都会变成 `disputed`，
并立即退出有效指导。作者在 UI 选择“采用此项”后，选中项成为 accepted，其他项成为
superseded。接受、编辑、裁决和遗忘都会先执行数据库条件版本声明；旧页面提交的版本会收到
409，而不会覆盖更新结果。

## 删除与遗忘

“删会话”和“忘记派生记忆”是两个动作：

- 删除会话默认保留作者已经接受的独立项目指导；未接受且只有这个会话一个来源的派生项会被
  擦除并留下墓碑；还有其他来源的条目只移除该来源。
- 遗忘某条记忆前，UI 先显示来源数量和涉及会话；第二次确认才擦除派生正文并建立墓碑。
- 遗忘不删除原始会话、作品正文、世界图谱或记忆文档。
- 项目整体删除仍经 Agent service 清理其记忆和墓碑。

## 用户界面

Agent 主页新增“跨会话记忆”区域。作者可以查看状态、来源数量和“Agent 建议/作者决定”，也可
手动创建、编辑、接受候选、裁决冲突和预览后遗忘。界面明确提示：只有已接受内容会进入新
会话。

## 验收结果

F15 的新验收记录由 `scripts/verify_feature.py` 执行并更新为 `passing`：

- 后端契约与长期记忆集成 25 项通过；
- 填充旧库迁移 1 项通过；
- 前端长期记忆交互 1 项通过；
- 额外回归覆盖 Agent API 29 项、F 定向后端 5 项、前端 Agent/store 21 项；
- Ruff check/format、Agent mypy、16 条 import-linter、前端 TypeScript 和定向 ESLint 通过；
- OpenAPI 已重新导出并生成前端类型。

完整历史 Agent 集成组还暴露一个既有 F14 非确定性排序：同一时刻登记的两条 pending write
按随机 ID 回读时，顺序可能与 SSE 清单相反；该单项独立重跑通过。它不改变写入内容，也不是
F 代码引入的行为，本阶段按范围纪律只记录而未修改 F14。

既有 Starlette 弃用提示、pytest cache 权限提示和部分前端测试的 MSW 未处理请求提示仍在；
没有调用真实计费模型、没有修改 `.env`、没有运行 mutation 或 benchmark。
